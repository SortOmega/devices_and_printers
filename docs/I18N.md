# Internationalization

## Supported Locales

The application currently supports:

- English (`en`)
- Spanish (`es`)

English is the default locale when the system locale is unsupported or cannot
be determined.

## Source of Truth

Localized resources live under `lib/l10n/`:

```text
lib/
├── l10n/
│   ├── app_en.arb                 # English template and source of truth
│   └── app_es.arb
├── core/
│   └── localization/
│       └── locale_provider.dart   # Detection, state, and persistence
├── app.dart                       # MaterialApp and provider wiring
├── main.dart
└── features/
    └── settings/
        └── presentation/
            └── screens/
                └── language_settings_screen.dart
```

The English ARB file is the template. Every user-facing message must have a
stable key in the ARB resources. Do not hard-code user-facing strings in
widgets, ViewModels, services, or platform code.

## Locale Resolution

Locale resolution must follow this order:

1. A persisted manual selection, when one exists.
2. The current system locale, when it is supported.
3. English (`en`) as the fallback.

The locale provider owns locale state, system-locale detection, and persistence.
`MaterialApp` receives the current locale and delegates supported-locale
configuration to the localization setup.

## Required Behavior

### Manual Selection

The Settings UI must allow the user to select English or Spanish. Changing the
selection must update the application without requiring a restart and must
persist the choice for future sessions.

### System Changes

The app must react to system-locale changes at runtime. If the user has not
chosen a manual locale, a supported system locale change must update the app.
When a manual override exists, system changes must not overwrite that choice.

Provide a clear Settings action for returning to the system locale. Clearing
the override must immediately resolve the current system locale again.

## Implementation Rules

- Keep locale persistence behind an injected storage abstraction.
- Persist locale identifiers such as `en` and `es`, not display labels.
- Treat invalid or removed persisted values as absent and resolve the locale
  using the normal fallback order.
- Use locale-aware formatting for dates, numbers, and other regional values.
- Add or update ARB entries before using a new localized string.
- Keep translations semantically equivalent and preserve placeholders across
  all supported ARB files.
- Test detection, manual selection, persistence, reset-to-system behavior, and
  runtime system-locale changes.
